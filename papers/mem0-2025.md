# Mem0: Building Production-Ready AI Agents with Scalable Long-Term Memory

- **Authors:** Prateek Chhikara, Dev Khant, Saket Aryan, Taranjeet Singh, Deshraj Yadav
- **Year:** 2025
- **Venue:** arXiv:2504.19413; ECAI 2025
- **Link:** https://arxiv.org/abs/2504.19413
- **Tags:** production, extract-consolidate-retrieve, graph-memory, locomo

## Core contribution

A production memory layer with an extract→consolidate→retrieve pipeline (plus a graph variant, Mem0g) that dynamically extracts salient facts and resolves conflicts. On LoCoMo: "91% lower p95 latency and saves more than 90% token cost" vs. full-context, and "26% relative improvements in the LLM-as-a-Judge metric over OpenAI" (66.9% vs. 52.9%; p95 latency 1.44s vs. 17.12s).

## Relevance to the project

A deployable reference architecture; documented critique: Mem0's update/delete decisions are delegated to the LLM without principled decay or scheduling — precisely the gap the project's controlled mechanism can address.

## Full-text confirmation (24/08/2026, Claude-read directly from the PDF, not Rafael-read)

Read in full (20 pages + Appendix B) at Rafael's request, comparing directly against the [`knowledge-as-infra-architecture-hypothesis.md`](../discussion/knowledge-as-infra-architecture-hypothesis.md) design. Confirms and sharpens the critique above:

- **Pipeline runs per message pair, not batched** (§2.1): extraction prompt combines an asynchronously-refreshed conversation summary + the last `m=10` messages + the new pair; an LLM extracts candidate facts; the update phase retrieves the `s=10` most similar existing memories and has the LLM choose ADD/UPDATE/DELETE/NOOP via a function-calling ("tool call") interface — "rather than using a separate classifier, we leverage the LLM's reasoning capabilities" (confirmed: LLM judgment throughout, no trained component).
- **Algorithm 1 (Appendix B) confirms no versioning**: `UPDATE` does `M ← (M \ {m_i}) ∪ {(id_i, f, "UPDATE")}` and `DELETE` does `M ← M \ {m_i}` — direct set replacement/removal, no diff or history kept.
- **Sharper than previously noted: Mem0 has *no* time-based decay at all** — `ClassifyOperation` triggers `DELETE` only when a new fact `Contradicts(f, M)`. There is no Ebbinghaus-style retention formula, no staleness/non-use signal anywhere. A memory that's merely outdated but not explicitly contradicted by anything new (e.g., a superseded threshold nothing directly conflicts with) is never removed. This is narrower than "uncontrolled forgetting" — it's "forgetting only by logical contradiction, never by obsolescence," which matters specifically for the legal-compliance case (most stale memory needs expiring, not contradicting).
- **Mem0g (graph variant) partial exception**: its "update resolver" marks obsolete relationships as *invalid* rather than physically removing them, "to enable temporal reasoning" — a rudimentary binary soft-delete flag, closer to an audit trail than base Mem0 has, but still not real versioning/diff.
- **Signal: confirmed fully automatic**, no human correctness signal anywhere in the ADD/UPDATE/DELETE/NOOP decision. Note also: Mem0 is not an RL paper — zero training, off-the-shelf GPT-4o-mini for both extraction and the update tool-call.
- **Headline numbers traced to source tables** (Table 1/2): J=66.88% (Mem0) vs. 52.90% (OpenAI baseline) → 26.4% relative, matches abstract. Query-time tokens 1764 vs. full-context 26031 → 93.2% reduction, matches ">90%". p95 total latency 1.440s vs. 17.117s → 91.6%, matches "91%". Honest caveat the abstract's "consistently outperform" undersells: Zep beats both Mem0 and Mem0g specifically on the Open-Domain category (J=76.60 vs. 72.93/75.71), and raw full-context still has the single highest overall J (72.90%) — Mem0's real win is the latency/token trade-off, not outright accuracy over everything.
