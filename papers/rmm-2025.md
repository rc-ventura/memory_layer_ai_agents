# In Prospect and Retrospect: Reflective Memory Management for Long-term Personalized Dialogue Agents

- **Authors:** Zhen Tan, Jun Yan, I-Hung Hsu, Rujun Han, Zifeng Wang, Long T. Le, Yiwen Song, Yanfei Chen, Hamid Palangi, George Lee, Anand Rajan Iyer, Tianlong Chen, Huan Liu, Chen-Yu Lee, Tomas Pfister (Arizona State University + Google Cloud AI Research + UNC Chapel Hill)
- **Year:** 2025
- **Venue:** ACL 2025, Volume 1 (Long Papers); arXiv:2503.08026
- **Link:** https://aclanthology.org/2025.acl-long.413/
- **Tags:** literal-rl, reinforce, policy-gradient, reranker, frozen-retriever, flat-memory, retrieval-side-rl

## Core contribution

Introduces **RMM** (Reflective Memory Management), two mechanisms for long-term personalized dialogue agents. **Prospective Reflection**: after each session, an LLM segments and summarizes interactions adaptively — topic boundaries can span one or several turns rather than following fixed turn/session boundaries — writing (topic-summary, raw-dialogue) pairs into a memory bank, merging with similar existing entries via an LLM-judged Add/Merge decision. **Retrospective Reflection**: a lightweight MLP reranker (not the retriever or the base LLM) sits between a frozen retriever (Contriever/Stella/GTE) and the generator, trained online via **REINFORCE** with a reward derived from which retrieved memories the generator LLM actually cites in its response. An ablation ("RR w/o reranker" — fine-tuning the retriever directly via RL instead of training the lightweight reranker) underperforms the full method; the paper attributes this to the labeled-data cost of full retriever fine-tuning and its susceptibility to catastrophic forgetting. Reports >10% accuracy improvement over a no-memory-management baseline on LongMemEval, outperforming MemoryBank, LD-Agent, and RAG baselines on MSC/LongMemEval.

## Relevance to the project

Two things make this a genuinely different data point from the rest of the corpus, not a repeat of an existing pattern:

1. **A third axis for the project's RL vocabulary (Sub 1.3/1.7).** The project's existing RL sources act on the *write* side — what to store, how to structure it, when to update it ([Memory-R1](memory-r1-2025.md), [Mem-α](reading-queue.md)) or on *prompt adaptation* ([Retroformer](retroformer-2024.md)). RMM's REINFORCE loop acts on the **retrieval/ranking side** instead — deciding what gets surfaced from an already-written memory bank — while never touching the base agent, the retriever, or the memory content itself. That's an operator category Sub 2.2/3.2 will need alongside write-side operators, not a substitute for them.
2. **Direct, citable evidence for the project's own non-parametric/controlled-mechanism principle.** The ablation showing that RL-fine-tuning the full retriever underperforms training a small controlled auxiliary component (the reranker) is peer-reviewed empirical support — not just an architectural preference — for exactly the design choice already made in [`../discussion/scope-and-terminology-decisions.md`](../discussion/scope-and-terminology-decisions.md) (non-parametric memory, controlled update). Candidate citation for the Sub 2.2 architecture document, not only the Sub 1.3 literature survey.

**Confirmed not hierarchical:** despite the "multi-granularity" framing, Prospective Reflection produces a flat, unstructured collection of (summary, raw-dialogue) pairs — topic segmentation is adaptive at write time, not a stack of abstraction layers, and no persistent link is stored between entries. Applying the project's own hierarchical test (explicit stored link between levels, not just multiple granularities mentioned) — this is **Flat (1D)**, same form as the [visual-synthesis mind map 1](../literature-review/visual-synthesis/README.md#1-memory-in-llm-based-agents) "Textual Form" branch, not Planar/Hierarchical.
